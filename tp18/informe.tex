\section{Introducción}
Se analizó el PCAP del caso Lumma del 19 de septiembre de 2024 para identificar comunicaciones sospechosas y cinco indicadores de compromiso. Se utilizó la VM disponible de Security Onion, con Snort, Zeek y Kibana.

\section{Proceso y resultados}
\subsection{Importación y revisión de alertas}
Se descargó el PCAP de Malware Traffic Analysis y se importó desde la carpeta Downloads con el siguiente comando:
\begin{quote}\small\ttfamily
sudo so-import-pcap\\
2024-09-19-file-downloader-to-Lumma-Stealer.pcap
\end{quote}
\captura{importacion.png}{Importación completada y análisis del PCAP con Snort y Zeek.}
En Kibana se seleccionó el intervalo del 19 al 20 de septiembre de 2024. Se visualizaron 147 registros y el panel NIDS mostró 0 alertas. Esto no demuestra ausencia de actividad maliciosa; se continuó con los registros HTTP y DNS.

\clearpage
\subsection{Análisis de HTTP y DNS}
El equipo \texttt{10.9.19.101} realizó tres solicitudes HTTP GET por el puerto 80: dos a \texttt{nhit66.com} y una a \texttt{back-kurwa.com}. Se observaron dos respuestas 200 y una redirección 301. No aparecieron solicitudes POST en el panel HTTP revisado.

Las rutas fueron \texttt{/test\_gate0117.php}, \texttt{/gate2.php} y \texttt{/gAySB.php}. Las tres solicitudes compartían un User-Agent que declaraba Windows NT 6.3 y Trident/7.0; este dato no permite identificar por sí solo el malware.
\captura{http-test-gate.png}{Registro HTTP con dominio, URI, IP de origen y User-Agent.}

Se observaron 24 registros DNS de tipo A: 16 con NOERROR y 8 con NXDOMAIN. Entre los dominios consultados aparece \texttt{back-kurwa.com}, también presente en HTTP. Los indicadores se contrastaron con el listado publicado para este caso [1].
\captura{dns-consultas.png}{Dominios consultados y respuestas DNS, mostrados como listas independientes.}

\section{Medidas de mitigación}
\begin{enumerate}[itemsep=5pt]
\item \textbf{Prevenir la infección:} descargar software de fuentes oficiales, evitar cracks y mantener el sistema y la protección antimalware actualizados.
\item \textbf{Detectar y contener:} monitorear HTTP y DNS, actualizar las reglas de detección y bloquear los indicadores confirmados del incidente.
\item \textbf{Proteger las cuentas:} ante una infección, aislar el equipo, revocar sesiones y cambiar contraseñas desde un dispositivo limpio; habilitar autenticación multifactor.
\end{enumerate}

\clearpage
\section{Conclusión}
El análisis permitió identificar cinco dominios vinculados al caso mediante registros HTTP y DNS y su contraste con información de referencia. Aunque NIDS no mostró alertas, la revisión del tráfico aportó evidencia útil para investigar la infección y proponer medidas de protección.
